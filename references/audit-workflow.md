# 三阶执行细节

## 工具链路由（按目标特征）

| 目标特征 | 路由 | 落地要点 |
|---|---|---|
| 混淆的 JS / Web 代码 | `webcrack` 或同类工具 | 不直接阅读混淆乱码 |
| 网络请求 / 加解密 | `Playwright MCP` 或 `Fetch MCP` | 授权范围内抓包；遇阻可退化为纯静态分析 |
| ELF / Mach-O / PE | REA 的 `Ghidra` / `Hopper` | 只取关键函数伪代码 |
| APK / DEX | `jadx` | 先看入口组件与网络层 |
| 常规元信息 / 清单 | `leanrea` 或等价本地 CLI | 阶段一默认路径 |

抓包受阻时退化为纯静态分析，并在报告里写明降级原因与对结论的影响。缺工具时给安装命令，继续推进可完成的静态推演，不因缺依赖停摆。

## 阶段一 · 侦察命令与攻击面清单

| 目标 | 命令 | 审计关注点 |
|---|---|---|
| 通用类型与架构 | `file {TARGET}` | 是否原生、是否加壳 |
| 可读字符串 | `strings -n 6 {TARGET}` | 硬编码密钥、内网地址、调试开关、错误码 |
| Mach-O 依赖 | `otool -L {TARGET}`、`lipo -info {TARGET}` | 引入的第三方库与签名状态 |
| Go 二进制 | `go version -m {TARGET}` | 依赖版本，比对已知漏洞 |
| ELF 依赖 | `readelf -d {TARGET}` | RPATH、弱符号绑定 |
| PE 头信息 | `objdump -p {TARGET}` | 加载器配置、ASLR / DEP 标记 |
| Electron 资源 | `npx asar list {TARGET}`、`npx asar extract-file {TARGET} {PATH}` | 主进程入口、预加载脚本、更新逻辑 |
| JS 清单 | `curl -s {URL}/package.json` | 仅公开可见端点 |

攻击面初判清单，逐项记录「有 / 无 / 待确认」：

| 面 | 关注内容 |
|---|---|
| 鉴权入口 | 登录、换票、刷新、单点、第三方回调 |
| 数据出入口 | 上传下载、导出、导入、分享链接 |
| 本地存储 | 配置文件、缓存、密钥库、日志文件 |
| 更新机制 | 更新源校验、签名验证、降级保护 |
| 第三方依赖 | 版本、许可证、已知 CVE |
| 通信安全 | 传输协议、证书校验、证书固定 |

门控判据：

| 观察结果 | 判定 | 动作 |
|---|---|---|
| 源码可读、逻辑自洽、攻击面清晰 | 无需深挖 | 直接梳理缺陷并出报告 |
| 压缩但结构完整 | 轻度混淆 | 阶段二反混淆后结束 |
| 控制流平坦化、字符串加密、自解码壳 | 重度混淆 | 进阶段二，再进阶段三 |
| 原生二进制且涉及内存或权限判定 | 需语义还原 | 进阶段三 |

## 阶段二 · 流量捕获、反混淆与证据固化

### 捕获

1. 用 Playwright 或 Fetch 类 MCP 打开目标，等待网络空闲。
2. 只触发与审计目标相关的最小交互集合（登录一次、发起一次业务请求），不漫游全站。
3. 导出 HAR 或结构化 JSON，记录条目序号、URL、请求头、响应体。
4. 先判断响应是否加密：可读 JSON、密文 base64、还是签名包裹。这决定后续走反混淆还是走伪代码。

### 反混淆

- 混淆代码不直接阅读，先交给 `npx webcrack {FILE} -o {OUT_DIR}`。
- 还原后按模块或函数切开，保留还原前后对应关系（原偏移、函数名），供报告溯源。

### 切片

- 单次读入控制在一个函数到一个小模块的量级。
- 大文件先用检索定位（字符串常量、错误码、URL 片段），再局部读取，不整文件灌入。
- 无 `context-mode` 一类工具时按函数边界手工切分，不影响流程推进。

### 记账（强制）

复制 `assets/audit_notes.template.md` 到工作目录命名为 `audit_notes.md`，边做边填。跨阶段事实以该文件为准；与笔记冲突的推测一律作废重查。

## 阶段三 · 深度审计与代码还原

1. 读 `audit_notes.md`，形成「已确认事实 / 待验证假设 / 待确认缺陷」三段清单。
2. 按目标类型取能力：

| 目标 | 工具 | 审计点 |
|---|---|---|
| 原生二进制 | Ghidra / Hopper | 缓冲区边界、整数溢出、权限判定分支、密钥派生与存放、反调试强度 |
| Android | jadx | 组件导出、Intent 校验、WebView 配置、本地存储、硬编码密钥、网络证书校验 |
| 运行时确认 | 动态调试 | 仅在静态无法确定时使用，记录断点条件与观察结果 |

3. 只取关键函数伪代码，不导出全量汇编。每确认一个缺陷，回填笔记并标注证据位置。

4. **能力缺失时的退出判据**：REA、Ghidra / Hopper、jadx 均不可用时，阶段三不得产出伪代码级结论，也不以「缺陷可复现」作为退出条件。此时：

   - 在 `audit_notes.md` 记下缺失能力与无法通过纯侦察回答的问题清单。
   - 报告中的相关项统一标注 `[证据缺失] 需进一步侦察`，置信度记「低」，不写「已确认缺陷」。
   - 报告尾「未覆盖项与风险缺口」写明降级原因、对结论可信度的影响，以及补齐依赖后的复测入口。
   - 只交付阶段一、二已落盘的可验证事实；不以推测填补本应由反编译引擎给出的结论。

   与 `rea-leanrea-router` 决策矩阵第 5 节的「两者均不可用」处理对齐。

## 工具安装（缺什么给什么，不假装已安装）

| 工具 | macOS | Windows | Linux |
|---|---|---|---|
| webcrack | `npm i -g webcrack` | `npm i -g webcrack` | `npm i -g webcrack` |
| jadx | `brew install jadx` | `choco install jadx` 或官网包 | 发行版仓库或官网包 |
| Ghidra | `brew install --cask ghidra`（需 JDK 17+） | 官网下载解压 | 官网下载解压 |
| Playwright MCP | `npx -y @playwright/mcp@latest` | 同左 | 同左 |

安装后通常需重开会话或重新加载 MCP 才生效。包名以官方安装页为准，装前先核对。

## 防幻觉规则

- **证据自检（强制）**：下结论前先读 `audit_notes.md` 检索对应证据；笔记中无支撑时输出 `[证据缺失] 需进一步侦察`，不得凭空补全，不得把推断写成事实。
- 没跑过的命令不写「已执行」，没抓到的流量不写「已捕获」。
- 伪代码未覆盖的分支标为推断，并说明依据强度。
- 数值型结论（偏移、长度、字段序号）必须注明来源位置。
- 三阶结论冲突时保留冲突并说明，不擅自选取有利的一条。
- 无法确认的可达性不要写成「可被利用」，写「静态可达，未验证利用条件」。
